**Biggest risk:** `POST /auth/register` accepts `role: "admin"` from any caller, and the socket
`join_conversation` handler performs no membership check — combining self-elevation with
real-time eavesdropping on any conversation.

## Week 1 — Unblock & De-risk

### [C-001] CRITICAL — Open admin self-registration via public API

- [ ] Restrict `registerSchema` role field to `z.literal('member')`
- **File:** `apps/api/src/modules/auth/auth.schema.ts:7`
- **Why:** Any API caller can `POST /auth/register` with `role: "admin"` and immediately become
  an admin. CORS does not protect against direct API access.
- **Fix:**
  ```typescript
  role: z.literal('member'),  // was z.enum(['admin','manager','member'])
  ```
  Privileged user creation is already correctly gated behind `requireRole('admin','manager')`
  in `users.router.ts` — that path stays as-is.

---

### [C-002] CRITICAL — `NOT NULL + ON DELETE SET NULL` FK constraint conflict

- [ ] Drop `NOT NULL` from `field_reports.reported_by`, `schedule_tasks.created_by`,
  `rfis.created_by`
- **File:** `apps/api/src/database/migrations/009_construction.sql:6,31`
- **Why:** PostgreSQL allows this DDL combination but at runtime any attempt to delete a user
  who created a field report, schedule task, or RFI will throw a constraint violation and
  roll back the delete.
- **Fix:** New migration `020_fix_not_null_set_null_conflict.sql`:
  ```sql
  ALTER TABLE field_reports  ALTER COLUMN reported_by DROP NOT NULL;
  ALTER TABLE schedule_tasks ALTER COLUMN created_by  DROP NOT NULL;
  ALTER TABLE rfis           ALTER COLUMN created_by  DROP NOT NULL;
  ```
  (If migration 017 already fixes this, verify and close.)

---

### [C-003] CRITICAL — Unauthenticated socket room join grants real-time message access

- [ ] Add `isParticipant` check to the `join_conversation` socket handler
- **File:** `apps/api/src/main.ts:30–34`
- **Why:** Any authenticated user can emit `join_conversation` with any conversation ID and
  receive all future messages for that conversation in real time. The REST API checks
  membership; the socket handler does not.
- **Fix:**
  ```typescript
  socket.on('join_conversation', async (conversationId: string) => {
    const allowed = await conversationRepository.isParticipant(conversationId, user.id);
    if (!allowed) return;
    container.realtimeProvider
      .joinRoom(`conversation:${conversationId}`, user.id)
      .catch((err) => console.error(`[socket] join failed`, err));
  });
  ```

### [H-001] HIGH — `/dev/clear-messages` endpoint has no authentication

- [ ] Add `authenticate` + `requireRole('admin')` middleware to the dev router
- **File:** `apps/api/src/modules/dev/dev.router.ts:9`
- **Why:** Any unauthenticated HTTP client can `POST /dev/clear-messages` in development or
  staging and wipe every message and translation from the database.
- **Fix:**
  ```typescript
  export function createDevRouter(container: AppContainer): Router {
    const router = Router();
    const authenticate = createAuthMiddleware(container.authProvider);
    router.use(authenticate, requireRole('admin'));
    // ... rest unchanged
  }
  ```

### [H-003] HIGH — JWT role claims go stale after an admin changes a user's role

- [ ] On role change (`PATCH /users/:id`), call `authProvider.revokeAll(userId)` to force
  immediate re-login
- **File:** `apps/api/src/modules/users/users.router.ts:105`, `JWTAuthProvider.ts:158`
- **Why:** `requireRole()` reads from the JWT. A demoted manager keeps manager-level access
  for up to 15 minutes (the access token TTL) after demotion.
- **Note:** The messaging router already shows the correct pattern — re-checking DB for
  voice/video permissions. The role system needs the same treatment or a shorter
  `ACCESS_TOKEN_EXPIRES_IN` in production (60–300s).

### [H-006] HIGH — Web client lacks concurrent refresh token race protection

- [ ] Apply the mobile `refreshPromise` singleton pattern to the web API client
- **File:** `apps/web/src/lib/api-client.ts:24–43`
- **Why:** Multiple parallel requests that 401 simultaneously each trigger an independent
  `attemptRefresh()`. Because tokens are single-use, the second rotation attempt receives
  a revoked token error and calls `clearSession()` — silently logging the user out.
- **Fix (mirrors `apps/mobile/src/lib/api-client.ts:29`):**
  ```typescript
  let refreshPromise: Promise<string | null> | null = null;

  async function attemptRefresh(): Promise<string | null> {
    if (refreshPromise) return refreshPromise;
    refreshPromise = (async () => {
      try { /* existing body */ }
      finally { refreshPromise = null; }
    })();
    return refreshPromise;
  }
  ```

### [H-007] HIGH — `IAIProvider` is a vestigial abstraction unused in any router

- [ ] Decide: remove `IAIProvider` + `MockAIProvider` + `aiProvider` from `AppContainer`,
  OR consolidate `ITranslationProvider` / `ISpeechProvider` / `IFieldExtractionProvider`
  under it
- **File:** `packages/types/src/providers/IAIProvider.ts`, `apps/api/src/container.ts:74–77`
- **Why:** The container wires `aiProvider` but no router injects it. Translation goes through

  `IFieldExtractionProvider`. `IAIProvider` misleads contributors about the architecture.
  Removing it is the simplest correct action.

### [H-008] HIGH — `REFRESH_TOKEN_SECRET` is validated, documented, and never used

- [ ] Remove `REFRESH_TOKEN_SECRET` from `packages/config/src/env.ts` and `.env.example`
- **File:** `packages/config/src/env.ts:19`, `apps/api/src/providers/auth/JWTAuthProvider.ts:158`
- **Why:** JWT access tokens are signed only with `ACCESS_TOKEN_SECRET`. Refresh tokens are
  UUIDs stored as SHA-256 hashes — not JWTs. The secret variable serves no purpose and
  misleads operators who rotate it believing it protects something.

### [H-009] HIGH — `GET /groups/mine` performs O(n) in-memory filter over all groups

- [ ] Add a `listByUserIdFull(userId)` method to `GroupRepository` that pushes the filter
  into SQL and replace the in-memory filter in the router
- **File:** `apps/api/src/modules/groups/groups.router.ts:22–25`
- **Why:** Every authenticated user who opens the app loads every group and every group's
  full member list into memory, then filters client-side. This scales with the total
  number of groups, not the user's membership count.
- **Fix (SQL):**
  ```sql
  SELECT g.* FROM groups g
  JOIN group_members gm ON gm.group_id = g.id AND gm.user_id = $1
  ORDER BY g.name
  ```

## Week 3 — Production Prep

### [M-001] MEDIUM — Web auth guard is client-side only (Next.js layout `useEffect`)

- [ ] Add `apps/web/src/middleware.ts` to enforce server-side route protection
- **File:** `apps/web/src/app/(dashboard)/layout.tsx:10–14`,
  `apps/web/src/app/manage/layout.tsx:50–57`
- **Why:** `useEffect` auth checks run after component mount. A direct URL visit renders
  the protected page before redirecting. For a management portal with sensitive
  construction data, this is a trust and information disclosure issue.
- **Fix:**
  ```typescript
  // apps/web/src/middleware.ts
  import { NextResponse } from 'next/server';
  import type { NextRequest } from 'next/server';

  export function middleware(request: NextRequest) {
    const refreshToken = request.cookies.get('refresh_token');
    if (!refreshToken && (
      request.nextUrl.pathname.startsWith('/manage') ||
      request.nextUrl.pathname.startsWith('/dashboard')
    )) {
      return NextResponse.redirect(new URL('/login', request.url));
    }
  }
  export const config = { matcher: ['/manage/:path*', '/dashboard/:path*'] };
  ```

### [M-002] MEDIUM — Settings `PATCH` broadcasts via N individual socket emits

- [ ] Emit to a shared broadcast room instead of looping over all users
- **File:** `apps/api/src/modules/settings/settings.router.ts:67–69`
- **Why:** On every settings update the handler fetches all users and emits an event to each
  user's personal socket room. With 200 users this is 200 `io.to(...).emit()` calls per
  settings change.
- **Fix:** At socket connect, join `broadcast:settings` room. On settings change:
  ```typescript
  void realtimeProvider.emit('broadcast:settings', 'settings_updated', updated);
  ```

### [M-003] MEDIUM — Photo upload in field reports has no explicit size limit

- [ ] Add an explicit byte-length check after base64 decode
- **File:** `apps/api/src/modules/field-reports/field-reports.router.ts:42–49`
- **Why:** The only size guard is the global `express.json({ limit: '15mb' })`. A caller can
  send up to ~11 MB of decoded image data without an explicit rejection.
- **Fix:**
  ```typescript
  const buffer = Buffer.from(data.photoBase64, 'base64');
  if (buffer.byteLength > 5 * 1024 * 1024)
    throw new AppError('Photo too large (max 5 MB)', 413, 'PHOTO_TOO_LARGE');
  ```

### [M-004] MEDIUM — No error context in server-side error logging

### [M-007] MEDIUM — Last-message preview is empty for audio/video messages

- [ ] Update the `findByUserId` conversation query to return a human-readable placeholder

- **File:** `apps/api/src/database/repositories/ConversationRepository.ts:85–90`

## Missing Pieces (for Phase 8 / Production Readiness)

- [ ] **TTS endpoint** — `ISpeechProvider` / `IAIProvider.textToSpeech` have no server route
  or mobile client integration. A `POST /speech/tts` route is absent entirely.
- [ ] **Email verification flow** — `emailVerified` is always `false`. The field exists in
  the schema and `AuthUser` but is never set to `true` anywhere.
- [ ] **Push notifications** — When the mobile app is backgrounded, the Socket.IO connection
  drops. There is no APNS/FCM integration for delivering messages to offline devices.
- [ ] **CSRF protection** — `POST /api/auth/login` and `/api/auth/refresh` on the Next.js
  layer accept any cross-origin POST with credentials. A CSRF token or `SameSite=Strict`
  cookie upgrade is missing.
- [ ] **Audit log** — Admin actions (user creation, role changes, deletions) are not logged
  with actor + timestamp + before/after values.
- [ ] **DB liveness in `/health`** — `GET /health` returns `ok` regardless of whether the
  database or Redis is reachable. Add a lightweight `SELECT 1` probe.

## Forward-Looking Risks (Phase 8 Deployment)

- **`LocalStorageProvider` returns relative URLs** — When `USE_REAL_STORAGE=true` and the
  API runs on a different host from the web client, `/uploads/...` paths break. Every media
  URL consumer needs updating.
- **`InMemoryQueueProvider` is process-local** — Horizontal scaling drops jobs silently.
  `BullMQProvider` must be implemented before multi-instance deployment.
- **`InMemoryRealtimeProvider` is process-local** — `SocketIOProvider` is ready but requires
  a Redis adapter (`@socket.io/redis-adapter`) for multi-instance deployments.
- **DB pool size is hardcoded** — `PostgreSQLAdapter` sets `max: 10`. Make this
  env-configurable before deploying to a cloud DB with connection limits.
- **Stale JWT role claims at scale (see H-003)** — With a live construction crew, an admin
  revoking a user's access needs near-instant effect, not up-to-15-minute lag.
